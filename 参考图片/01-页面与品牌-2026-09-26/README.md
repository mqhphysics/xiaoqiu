## 1. 本轮结论

可以用已认可的效果图作为实现参考，不需要用户手工把整张网页切成几十块。实现者应把页面拆成可复用组件，把照片、线稿、图标和装饰外框作为独立素材。

效果图主要确定外观；页面行为、数据来源、权限、手机布局和各种状态需要短规格补齐。完成效果图不等于完成软件架构，更不等于已经实现产品。本项目已有 Taro + React 前端、共享导航、Repository 和 API，沿用现有结构进行视觉升级即可。

推荐流程：

1. 本轮记录已确认的设计，保存参考图。
2. 小范围补齐素材与示例图：新图标、D 外框、校园建筑线稿；补主队页和手机布局。
3. integrator 接收本文件，核实当前工作区与已有修改，明确组件和页面的唯一写入者。
4. 先实现公共导航、背景体系、首页及一个真实数据组件，在浏览器里对照。
5. 视觉基准稳定后推进其他页面，最后验证数据、状态和多端行为。

无需先搭新的服务、换框架或引入复杂设计工具。Figma 可选；参考图、素材清单、本文约定和浏览器实测已经能构成第一轮交接输入。

## 5. 校园建筑线稿设计规格

### 5.1 绘制对象

三张照片对应同一场馆，用不同角度互相补充。需要保留：

- 宽大的中央挑檐、轻微起伏的屋顶轮廓和厚檐口。
- 檐下大开口与少量立柱；中央主席台及台阶。
- 向左右展开的弧形侧翼。
- 层层向球场下降的阶梯看台与通道分区。
- 前方绿茵场的边界、中线或少量跑道弧线。
- 必要时保留少量细长竖杆作为结构特征，避免过度强调。

不逐一描座椅、窗格、人物或广告字。清晰照片作为正面比例主参考，侧视照片补充厚度与弧面。不同时间照片里的附属设施有差别，不机械叠加所有细节。

### 5.2 画法

以低饱和灰绿色或暖灰单色线条绘制，少量极浅块面表示檐下与体积。画风接近现有效果图里的背景建筑，但结构必须让人辨认出提供的场馆。

先提供清楚、正常浓度、透明背景的母版，页面中再控制透明度；避免源文件本身已经过淡，叠加后完全消失。表格和正文背后留干净区域。

推荐先做两张母版：

1. 正面全景：中央挑檐、主席台、左右看台及前方少量场线。
2. 斜侧局部：中央体块、弧形侧翼与阶梯看台，有空间纵深。

全景、局部、镜头位置变化优先通过裁切与定位实现。具有辨识度的建筑结构不随意镜像；必要的反向构图应重画，避免建筑关系错误。

### 5.3 页面分配建议

| 页面 | 建筑表现 | 视觉重量 |
| --- | --- | --- |
| 首页 | 真实摄影为主，边缘辅以看台或场线局部 | 摄影强、线稿轻 |
| 赛程 | 正面主席台与看台轮廓，分布在页头或侧边 | 中轻，比赛列表清楚 |
| 数据 | 球场几何线及很淡的看台局部，减少图形数量 | 全站最克制 |
| 主队 | 斜侧看台与队旗/球队封面组合 | 可比数据页更丰富 |
| 我的 | 校园边缘场景与主队封面，沿用相同线稿家族 | 照片承担主要氛围 |

以上是配置建议，不要求每页都有大背景插画。窄屏优先保留一个小型局部，减少遮挡。

### 5.4 可直接用于生成线稿的提示词

> 请根据我提供的三张同一校园足球场主席台与看台照片，绘制用于“晓球”网站背景的简化建筑线稿。参考它们的实际结构与比例，保留宽大的中央挑檐、起伏屋顶、檐下开口、中央主席台、两侧弧形建筑、阶梯看台和少量前方球场线。清晰正视照片用于主要比例，侧视照片用于理解厚度与转折。画风为精致的现代建筑简笔线稿，灰绿色单色，少量浅色块面，线条克制、有层次。省略人物、文字广告、逐个座椅、复杂窗格及无关高楼。不要直接抠图、照片滤镜描边或替换成通用体育场。输出独立透明背景素材，线条本身保持正常可见浓度，不把透明棋盘格画进图片。先生成正面全景；下一张再生成斜侧局部，保持相同线宽和画法。不画网页、导航、标题或卡片。它将作为暖白校园体育网站的低对比背景，中央需要给阅读内容留出空间。

## 6. 如何拆分：少量素材 + 复用组件

| 对象 | 实现形式 | 原因与边界 |
| --- | --- | --- |
| 导航、标题、正文、日期、比分 | 实际文字与 Taro/React 组件 | 能选择、缩放、换行，内容来自数据 |
| 比赛卡片、榜单、筛选、公告 | 组件与样式 | 能点击、切换及显示错误/空态 |
| 大小间距、背景分区、斜切、边界 | CSS/SCSS 为主 | 能随窗口与内容变化 |
| 品牌图标 | 当前透明 PNG，后续可人工整理矢量版 | 本轮不强制重画 |
| 校园建筑 | 独立透明 PNG；可获得可靠矢量源时再导出 SVG | 生成 PNG 不等于已经有可编辑矢量 |
| 比赛与校园摄影 | 独立图片素材 | 不从整页图烘焙文字和界面 |
| 主队 D 外框 | 独立透明装饰层 | 与不同球队队徽组合，不能与松树图案焊死 |
| 球队队徽 | 独立球队资源与占位逻辑 | 同一球队跨页面保持一致 |
| 小图标 | 沿用/整理已有统一图标方案 | 不为本次视觉改造强制引入新库 |

先准备约 5—8 个关键素材即可：当前品牌、主队外框默认与悬停（可共用素材由样式变化）、建筑正面与侧面、首页摄影、主队封面。球队资源按已有数据逐步整理。复杂纹理可后置，不要求用户手动逐像素切割。

注意首页效果图内的摄影尚未有独立干净原图。优先取得原素材或按选定构图生成无文字图片；不得把包含标题、斜切白块的整页裁片误作通用照片。

## 7. 建议的前端组织与交互约定

以下名称是建议职责，不代表已经新建这些文件。

- PublicShell：沿用现有，统一桌面顶部导航与移动底部入口。
- BrandMark：封装图形、文字组合、尺寸及替代文本。
- TeamNavBadge：D 外框 + 队徽插槽 + 选中、焦点、悬停与回退状态。
- CampusBackdrop：只负责装饰；按 home/schedule/data/team/me 选择母版、位置、裁切和强度。
- 现有 TeamCrest / MatchCard / PostCard / DataState：统一样式与状态，按需求增加布局变体。
- 页面：组合共享组件，继续通过现有 Repository 获取数据，不复制公共导航和球队映射。

### 7.1 主队按钮

- 已登录且有主队：中央队徽来自当前主队，点击沿用主队页路由。
- 已登录未选择：显示中性主队占位，进入现有选择流程。
- 游客：仍可进入主队入口的游客引导；需写入选择时按现有规则引导登录，不把游客误判为会话。
- 缺队徽/加载失败：回退球队简称或中性图形，布局不跳动。
- 当前页高亮、键盘焦点与鼠标悬停分别表达；触屏不依赖 hover。
- 外框可轻微浮起或局部提亮。动效支持减少动态偏好，不遮住中心图案。
- 背景与装饰层不拦截点击，不被读屏当成内容；按钮有“打开主队/打开某队”可访问名称。

当前架构文字中“圆形主队入口”与 D 的异形外框存在外观表述差异。用户本轮明确选择 D；保留居中主队入口的功能与顺序，后续由 integrator 同步基线措辞，本文件不直接修改权威架构。

### 7.2 页面必须保留的行为

| 页面 | 功能底线 | 图片不能替代的状态 |
| --- | --- | --- |
| 首页 | 搜索、比赛详情、公告、动态与发布入口 | 加载、无公告/无比赛、图片失败、游客受限操作 |
| 赛程 | 日期/状态筛选、比赛详情、返回与筛选保持 | 无结果、延期/取消、待定球队、错误重试 |
| 数据 | 赛季/组别/榜单切换及解释 | 无数据、暂无排名、暂定统计、更新时间 |
| 主队 | 选择与更换主队、关注、战绩/阵容 | 未选主队、游客、队徽缺失、保存失败 |
| 我的 | 身份资料与实际权限入口 | 游客、普通学生、关联球员、队长/管理角色差异 |

公告若轮播，应有手动切换/暂停、聚焦与悬停暂停；重要改期信息需稳定可见。列表和统计的内容必须来自现有事实，不照抄生成图的数字。

“转会市场”不因出现在效果图就进入首发范围；“管理球队”仅按实际权限显示并由后端校验；“设置提醒”等能力先确认已有实现，再决定保留方式，不能交付无响应按钮。

## 9. 建议的实施节奏与 integrator 交接

### 第一步：接手盘点

核实当前 checkout、分支、未提交修改、既有运行进程与本轮文件所有权。本轮检查到的是 codex/h5-refinement，但接手时必须重查。docs/tasks 的 P4 卡为历史交接记录，不能直接按里面的老基线与旧 worktree 开工。

由 integrator 确定新的实施任务和共享文件写入者。确需并行时再给任务独立分支/worktree；本轮没有自动创建或派发任务。

### 第二步：公共壳层与首页试做

先做 BrandMark、TeamNavBadge、背景配置、共享样式，再接首页。保留真实搜索、导航与数据请求。

首轮交付：一个实际可访问的首页，在桌面与手机尺寸有浏览器截图，主队按钮与现有会话/选择链路能工作。用这一页确定间距、背景浓度与组件质感，避免每页各自猜测。

### 第三步：复用到其他页面

公共约定稳定后，推进赛程/数据与主队/我的。两组可以由 integrator 按人员和文件范围安排；不要让多个实现者同时改 public-shell、设计令牌和全局样式。

## 10. 多端与验收约定

### 10.1 响应式

以下为建议验证尺寸，不是已确认断点：

- 桌面：1440 与 1920 宽，统一最大内容宽度，保证首页首屏有焦点比赛。
- 中间宽度：约 1024，侧栏允许下移，筛选可分行。
- 手机 H5：390 与 430 宽，保留底部五入口；背景减少，比赛卡片重排。
- 密集表格：根据实际字段选择局部横向滚动或精简列，页面本身不能横向溢出。
- 小程序：共用组件和数据；涉及 SVG、遮罩、滤镜或 H5 专用能力时使用可验证的替代资源。构建成功不等于开发者工具或真机验收通过。

### 10.2 视觉验收

- 全站品牌、D 外框和同一球队队徽一致。
- 建筑能对应参考场馆；背景不遮挡文字、不抢按钮注意力。
- 内容可读、可点击；长队名、宽窄比分、缺头像及缺图片不破版。
- 当前图标在浅色/深色背景检查边缘，小尺寸检查足球与弧线辨识。
- D 外框用绿色、红色、蓝色及异形队徽检查适配。
- 与参考图比较时使用同视口；接受真实字体渲染与动态内容差异，不以整页贴图追求像素相同。

### 10.3 功能与工程验收

- 导航、游客、登录/退出、切换主队及刷新后的状态不回退。
- 筛选、详情、公告、动态与现有权限链路实测；特别覆盖跨页的主队更新。
- 加载、空、错误、重试和资源失败有清楚状态。
- 文字对比、键盘焦点、可访问名称及减少动态偏好检查。
- 首轮视觉修改按范围执行 typecheck、相关现有测试、H5 构建与浏览器验证；完整集成按当前项目基线执行质量门，不复制历史卡中把测试数据库设为日常数据库的做法。

供实施阶段核对的当前脚本：

~~~powershell
pnpm --filter @xiaoqiu/mini-program typecheck
pnpm --filter @xiaoqiu/mini-program test
pnpm --filter @xiaoqiu/mini-program build:h5
pnpm --filter @xiaoqiu/mini-program build
git diff --check
# 完整集成阶段，按项目基线配置隔离测试环境后：
pnpm check
~~~
