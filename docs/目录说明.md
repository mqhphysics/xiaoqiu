## 根目录安排

```text
xiaoqiu/
├─ 打开晓球网站.cmd           日常启动文件
├─ docs/                     产品、规划、验收、运维与历史文档
│  ├─ 目录说明.md             这份中文导航
│  ├─ architecture/           唯一产品与技术基线
│  ├─ status/                 进度快照、功能分层与真实赛事准备
│  ├─ planning/               后续讨论方案，不代表功能已实现
│  ├─ testing/                启动、演示验收和测试截图
│  ├─ runbooks/               开发、部署、备份、恢复、回滚手册
│  ├─ development/            贡献与开发协作说明
│  ├─ research/               竞品、开源方案研究
│  ├─ decisions/              技术决策模板；目前没有已接受的 ADR
│  ├─ tasks/                  新任务入口；旧 P4 卡已归档
│  ├─ maintenance/            分类清单与本次整理记录
│  └─ archive/                旧架构、旧实施方案、旧任务和技术验证
├─ 参考图片/                  设计参考原件和概念图集中入口
│  ├─ 图片索引.html            无需启动服务的本地缩略图页面
│  ├─ 01-页面与品牌-2026-09-26/ 10 张参考图、视觉基线、首页任务书、来源清单
│  └─ 02-登录页概念-2026-10-01/ 2 张概念图、研究记录、生成提示词
├─ 工程配置/                  隐藏工程配置的快捷方式与用途说明
├─ apps/                      产品代码：网站、小程序、API、管理后台、Worker
├─ packages/                  契约、API Client、设计令牌、领域工具
├─ prisma/                    数据库模型、迁移、Seed 入口
├─ infra/                     Docker 与部署配置
├─ scripts/                   启动脚本及本次显示/恢复脚本
└─ private-data/              本机私有资料、运行日志、备份与整理前快照
```

根目录常见配置、项目 `README.md`、`AGENTS.md` 和依赖/临时工作区设为 Windows 隐藏。关闭资源管理器“显示隐藏的项目”后，根目录可见的普通文件只剩启动文件；这些配置仍在真实工程根目录，开发工具可正常读取。`工程配置/` 内是指向原文件的快捷方式，没有第二套配置。

`apps/`、`packages/`、`prisma/`、`infra/` 保留英文名与路径，因为工作区、构建、容器和应用之间按这些路径相互引用。目录职责在这里用中文解释，避免连带修改业务工程。

## 图片的四种类型

| 类型 | 实际位置 | 怎么区分 |
| --- | --- | --- |
| 设计参考与概念图 | 根目录 `参考图片/` | 用来讨论外观；静态概念图不代表功能已经开发 |
| 前端实际素材 | `apps/mini-program/src/assets/`，重点是 `home-visual/` | 品牌、主队框、首页摄影、建筑线稿、导航 SVG；被页面代码引用 |
| 演示队徽、头像 | `apps/api/demo-media/crests/`、`portraits/` | 当前各 16 张，供虚构演示使用；不是校园球队真实授权档案 |
| 历史验收截图 | `docs/testing/screenshots/p4-interface/` | 4 张旧 P4 页面截图，用于追溯当时外观，不能证明当前页面状态 |

另外，`private-data/media/avatars/` 是本机上传媒体；`private-data/runtime/` 包含运行、浏览器验证的日志和临时截图。这些是私有或临时资料，不混入设计参考图库，也不公开提交。当前只按目录职责检查，没有逐份审阅用户上传的私有材料。

## 文档哪些有用，哪些可以收起来

- **当前要看：** 最终架构、启动说明、演示验收手册。
- **讨论时有用：** 后台规划、登录页方案、页面与品牌参考。文中的“计划”“建议”保留原含义，不当作现有功能。
- **开发运维时有用：** 协作规范、贡献说明、Runbook、ADR 模板。Worker 手册仍写明是占位流程；部署/备份指令需结合实际环境核对。
- **查来龙去脉才看：** 旧核心架构、A/B 方案、v0.1/v0.2 实施方案、P0–P4 任务、早期测试与 Spike；集中在 `docs/archive/`。
- **低价值但保留：** 早期运行日志、空目录历史说明。它们不指导当前开发，本次没有删除。
- **谨慎使用：** `research/deep-research-report.md` 是旧研究导出，含无法在本地跳转的会话引用和旧技术候选；保留作背景，不作为当前技术路线或现时开源状态的依据。

## 恢复显示与追溯移动

在项目根目录执行下面命令，可恢复本次整理前的隐藏状态：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\maintenance\set-folder-visibility.ps1 -Mode Restore
```

重新隐藏使用 `-Mode Clean`。具体移动对应关系、验证结果和回退说明见[整理记录](maintenance/目录整理记录-2026-10-01.md)。整理前的文件哈希、文档副本和显示属性保存在本机 `private-data/organization/2026-10-01/`。
