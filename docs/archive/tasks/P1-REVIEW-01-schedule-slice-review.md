# P1-REVIEW-01 赛事与赛程纵向切片复审

## 目标

只读审查 P1 第 2 轮三个开发分支是否满足纵向切片目标，并指出集成风险。不得修改文件，不得合并分支。

## 分支

不创建开发分支。可在主仓库或单独只读 worktree 中审查。

## 读取范围

- `main`
- `ai/p1-api-schedule`
- `ai/p1-admin-schedule`
- `ai/p1-mini-readonly-schedule`
- `docs/implementation/晓球方案A详细实施方案v0.2.md`
- `AGENTS.md`
- 本轮任务卡

## 审查重点

1. 后端
   - 组织隔离是否系统性落实。
   - 发布命令是否写 AuditLog 和 OutboxJob。
   - 发布后是否避免原地覆盖。
   - OpenAPI、contracts、DTO 命名是否一致。
   - 数据库唯一约束和索引是否足够支撑 P1 查询。

2. 后台
   - 是否完成真实纵向流程，而不是静态展示。
   - API adapter 是否集中。
   - 提交中是否防重复提交。
   - mock/API 模式是否清晰区分。

3. 小程序
   - 页面是否可在 weapp 和 H5 构建。
   - 只读数据层是否集中。
   - mock ViewModel 是否容易与后端对齐。
   - 窄屏文字是否可能明显溢出。

4. 集成
   - 是否存在公共文件越权修改。
   - 是否修改 `pnpm-lock.yaml`。
   - 是否引入真实密钥或个人信息。
   - 三个分支是否有明显冲突。

- 不修改代码。
- 不运行破坏性命令。
- 不自行修复问题。
- 不把缺少后续范围功能当作本轮失败。
