# P4-00 集成负责人交接

## 1. 角色与目标

你是 P4 细节完善轮次的集成负责人，只在以下工作区和分支工作：

- 工作区：`.worktrees/p4-integrator`
- 分支：`integration/p4-detail-polish`
- 基线提交：`e5f834f feat: complete v1 public experience`

本轮第一优先级是把 H5 网站打磨成可逐页验收的产品。微信小程序与 H5 共用 Taro + React 代码，必须保持可构建，但本轮不以微信开发者工具或真机验收作为开发阻塞项。

## 2. 必读资料

1. `docs/architecture/晓球产品与技术架构最终版.md`
2. `AGENTS.md`
3. `docs/testing/演示验收手册.md`
4. 本任务卡

## 3. 受管分支

| 工作流 | 分支 | 工作区 | 默认范围 |
| --- | --- | --- | --- |
| 界面细节 | `ai/p4-interface-polish` | `.worktrees/p4-interface` | 登录、全局框架、首页和视觉细节 |
| 赛事体验 | `ai/p4-competition-experience` | `.worktrees/p4-competition` | 赛程、数据中心、比赛详情和赛事交互 |
| 账户与社区 | `ai/p4-account-community` | `.worktrees/p4-account-community` | 我的、球队、球员、动态和账户体验 |

用户后续下达的明确要求优先于上表默认范围。若两个任务需要修改同一个公共文件，先指定唯一写入者，其他任务只提交接口建议。

## 4. 负责人工作循环

1. 记录三个分支当前 HEAD 和用户分别下达的验收要求。
2. 检查各分支工作区是否干净，禁止替开发任务提交未完成修改。
3. 开发任务报告完成后，先审查 diff、运行该任务的定向测试，再决定是否允许进入集成。
4. 有问题时输出具体文件、行号、影响和返工标准；不得只回复“继续完善”。
5. 通过后按风险从低到高逐个合并到 `integration/p4-detail-polish`，每次合并后立即验证，避免一次合并三个分支后再排错。
6. 全部分支集成后运行完整质量门，并完成桌面与移动 H5 的视觉检查。
7. 输出集成报告和最终提交哈希，交给主任务复核；不得自行合入 `main` 或推送生产部署。

## 5. 审查重点

- 不允许演示账号、公共密码、真实密钥或个人敏感材料出现在界面和提交中。
- 登录、游客、退出和受限操作的状态必须一致，不能只隐藏按钮。
- 五个主入口顺序、居中主队入口和详情返回逻辑不得回退。
- 页面必须使用真实 API；mock fallback 必须明确标识，不能静默伪装为成功。
- 比赛评分、评论、赛程和榜单修改必须保持组织隔离、鉴权和数据库约束。
- 桌面与移动端不得出现遮挡、溢出、不可点击或空白状态。
- 不允许开发任务修改 `pnpm-lock.yaml`；依赖更新由集成负责人统一处理。

## 6. 集成质量门

```powershell
$env:DATABASE_URL = 'postgresql://xiaoqiu:xiaoqiu-local-only@localhost:5432/xiaoqiu'
$env:TEST_DATABASE_URL = $env:DATABASE_URL
pnpm check
pnpm --filter @xiaoqiu/mini-program build:h5
pnpm --filter @xiaoqiu/mini-program build
git diff --check
```

此外必须验证：

- `http://127.0.0.1:10087/` 可访问；
- `/api/health/ready` 返回 API 与数据库正常；
- 至少使用普通用户、球员/队长和管理员三类账号走查；
- 桌面与移动宽度分别截图检查关键页面；
- 微信小程序构建成功，但开发者工具和真机验收留到 V3 微信试运行版。

## 7. 交付报告

最终报告必须包含：合并的分支与提交、返工记录、测试命令与结果、截图位置、未解决问题、对 `main` 的合并建议。没有完成完整质量门时，只能标记为“有条件通过”。
