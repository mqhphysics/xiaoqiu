# P2-SB-12-02 公开 H5 网站主体

## 目标

把当前 Taro 公开端从技术骨架提升为可在浏览器验收的校园足球赛事网站，同时保持微信小程序构建兼容。

## 分支

`ai/p2-public-h5-site`

## 独占写入范围

- `apps/mini-program/`
- 该应用内测试和说明

不得修改 Prisma、API、contracts、Admin Web、根配置或 `pnpm-lock.yaml`。需要公共契约变化时只在报告中提出。

## 产品范围

首屏直接进入真实产品，不制作营销落地页。完成以下公开流程：

```text
首页赛事概览
-> 赛事列表/详情
-> 赛程
-> 球队列表
-> 球队详情与公开名单
-> 比赛详情
```

“比赛数据、社区、登录”等未完成模块可以保留明确的不可用状态，但不得伪装成已接入功能。

## 页面和交互

- H5 桌面端使用稳定的顶部/侧边导航与受约束内容宽度，不把手机页面简单放大。
- 手机端使用紧凑导航，确保后续微信小程序可复用。
- 首页首屏明确显示“晓球”和当前赛事/下一场比赛等真实状态，首屏下方露出下一段内容。
- 赛事、赛程、球队均提供加载、空、失败和重试状态。
- 赛程支持日期/阶段扫描；球队列表支持快速定位。
- 球队详情显示公开名称、报名/名单状态、公开球员姓名和球衣号；不显示学号、手机号、导入告警或后台审核备注。
- 所有固定格式模块使用稳定网格/尺寸，桌面 1440px 和手机 390px 不重叠、不溢出。
- 使用与校园足球真实内容相关的位图资源或球队视觉占位资产；不得使用渐变球、纯装饰 SVG 或与产品无关的库存图。若缺少最终资产，在报告中列出集成负责人需要补充的资产位。

## 数据接入

沿用现有 API adapter，新增并严格使用：

```text
GET /api/public/tournaments/{tournamentId}/teams
GET /api/public/tournaments/{tournamentId}/teams/{teamId}
```

字段以 `ROUND-03-assignment-guide.md` 和后端任务卡为准。

- API 模式失败时必须显示错误和重试，不得静默切回 Mock。
- Mock 模式必须有明显开发标识，只用虚构数据。
- Repository/adapter 集中，页面不直接散落 `Taro.request`。
- 不手写与 API 重复的业务请求 DTO；若生成 Client 尚未集成，保持单一 adapter 并在报告中登记替换点。

## 验收

- `dev:h5` 可在浏览器访问完整公开流程。
- `build:h5` 与 `build`（weapp）均通过。
- 既有快速报告 Spike 测试不回归，但它不出现在公开主导航核心位置。
- 新增核心转换/筛选逻辑测试。
- H5 入口体积警告有记录；本轮不为消除警告引入大规模依赖。
- 桌面和手机截图检查无空白、遮挡、按钮文字溢出或不可点击主流程。
