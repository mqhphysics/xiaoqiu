# 学生、用户、球员与赛事赛季

本轮实现对应2026-10-16用户确认的关系。代码、迁移与演示资料先在隔离数据库验证；当前共用数据库的导入及日常网站切换需单独获批，不能把隔离验收写成已上线。

## 身份和资料

| 资料 | 保存内容 | 关联规则 |
| --- | --- | --- |
| StudentRecord 学生 | 姓名、组织内唯一学号、性别、学院、年级、核验状态、演示来源 | 用户与球员的共同基础；通过稳定ID关联 |
| User 用户 | 登录凭据、昵称、邮箱、简介、头像、个人背景、引导状态 | 一名学生至多一个账号；注册后可存在，没有球员也能使用 |
| PlayerProfile 球员 | 学生关联、球员头像/照片/背景、位置、惯用脚、能力值、足球介绍 | 无注册账号也可建立；不会仅凭姓名认领或合并 |
| RoleAssignment 身份 | 教练、信息员、赛事管理员及队长等权限 | 附属于账号，队长同时绑定球队；每次写入重新检查授权范围 |
| Team 球队 | 球队的稳定基础身份 | 赛季显示资料保存在TeamRegistration中，名单保存在各版本锁定快照中 |

自助注册根据学号寻找学生档案并核对姓名，但不自动核验或获得球员权限。已核验学生完成网站引导后，才能确认稳定ID关联的球员档案；若资料不符，可联系管理员核验或使用认证申请。普通用户可提交球员认证申请。首次引导与确认仅接入H5。

管理中心的姓名/学号编辑同步关联用户及当前球员展示资料，保留过去已锁定名单的姓名和号码。旧账号的登录名、密码、动态与历史不会因为这次归档删除。原本没有真实姓名/学号证据的管理员账号保留为“旧资料待核验”，不编造真实学生身份。

演示目录为300名学生，其中224名沿用已有球员；新增30个完整演示账号组成“本轮演示资料”的用户组。旧账号另行保留，因此全组织用户总数不等于30。演示学号使用99前缀，不代表真实学籍。头像各不相同，背景与球员照片优先复用已有合法演示素材；账号、球员图片和待审投稿都在对应人员详情查看，动态正文与图片继续在帖子审核中处理。

## 赛事和赛季

CompetitionDefinition提供新生杯、计科杯、绿茵杯，每项分男足和女足，显示为“绿茵杯（男足）”等六个赛事。Season独立提供演示赛季和2026。Tournament是具体赛事在某赛季的实例；同一赛事同一赛季只能一个实例。

保留绿茵杯男足演示赛季原有16队、224名球员及32场比赛。其他组合没有公布报名或赛程时明确显示空状态，不能回落到演示赛事。管理中心可建立空的赛事草稿，队伍、分组、淘汰赛和比赛须按实际情况配置，不自动生成。

2026正式赛季按自然年作为资料归档周期；具体赛事开赛日期仍由赛事安排决定。球队赛季资料编辑仅影响该赛事的报名展示，不修改球队基础资料、其他赛季或锁定名单。用户可在管理中心追踪这些关联。

## 信息员记录质量分

| 事件 | 分数或状态 |
| --- | --- |
| 首次授予信息员身份 | 100分 |
| 总管理员核实差错成立 | 正常期扣10分；考察期扣20分；仅反馈不扣分 |
| 连续三场已审核合格的不同比赛 | 加10分，上限100；同场重复提交或重放不重复奖励 |
| 确认差错 | 中断连续合格进度；同一报告同一差错事项只处理一次 |
| 低于60分 | 冻结信息员资格；60分仍可正常记录 |
| 持有资格的一个完整赛季没有合格贡献 | 冻结信息员资格，不冻结普通账号 |
| 冻结后申请复训并获总管理员批准 | 先等待7天，再恢复为考察状态 |
| 首次恢复 | 分数补至至少60；之后恢复保留原分数，不反复补分 |
| 恢复后的考察 | 至少90天，且经过恢复之后开始的一个完整正式赛季；按实际差错发生时段判断扣10或20，不能用延迟审核改变规则 |
| 考察结束 | 分数至少60且满足时间和完整赛季要求后，回到每次扣10分 |
| 0分 | 封禁信息员资格，不能重新申请；普通账号保留 |
| 裁定有误 | 通知后7天内申诉；管理员复核成立后返还原次扣分，保留撤销流水 |

分数记录包含理由、操作者、前后分数和关联纠错；本人不能裁定自己的差错。资格冻结、冷却、封禁由后端检查，重新登录或重新申请身份不能绕过。接口使用版本检查、组织隔离和幂等键防止重复处理；低分可继续申请复训，但不能靠重复复训无限恢复分数。

三场合格奖励是在比赛终审确认时计入。之后若发现该场差错，会另行记录纠错、扣分并中断当前连续进度，不抹去已有审核或分数流水。

## 实现位置与边界

- 数据模型：`prisma/schema.prisma`，本轮两条增量迁移。
- 学生、关联、比赛目录、赛季球队、质量分：`apps/api/src/campus/`。
- 隔离演示生成器：`apps/api/src/database/seed-campus-directory.ts`，只接受专门的隔离库名称；不在共用库运行Seed。
- 管理中心：`apps/admin-web/src/features/adminCenter/CampusDirectory.tsx`、`CompetitionPicker.tsx`、`TeamSeasons.tsx`、`ReporterManagement.tsx`。
- 网站引导、选择器、质量分：`apps/mini-program/src/components/campus-context/`及`pages/me/my-identities.h5.tsx`。
- API契约：Nest DTO及`docs/api/openapi.json`；`packages/api-client/src/generated/`由固定版本工具生成，不手改。

微信小程序的界面、引导、导航和布局不改。共享PublicShell只增加平台适配入口，微信默认适配器返回原有内容；共享比赛详情的新增纠错入口在微信默认返回空。数据库和注册API属于公共后端，另一端会沿用新增关系及兼容的注册校验，需要在其后续集成时单独进行设备验收。
