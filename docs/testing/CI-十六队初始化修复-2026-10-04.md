# 十六队初始化与账号登录版验收

分支：`codex/release-account-only`。基线：main `59d60e4fb82042a880bab196df08a1f7a0fab1f6`。独立工作树构建，不覆盖主目录、其他 Agent 的进行中修改或日常 3000 预览。GitHub Actions 最终运行结果由交接回复提供，本文件记录本地实际检查。

## CI 根因及赛事含义

main 的 CI `37137740401`、`37140390631` 在首次 seed 失败：赛事只初始化前八队锁定名单，社区初始化却读取全部球队。修复保留完整业务含义：2026 有 16 支参赛队，四组各四队单循环，小组前二共八队晋级淘汰赛；每队锁定 14 人名单，八人制首发。2025 历史赛事仍为八队。

2026 共 32 场演示比赛，四组积分与八强签位一致。回归从全新 schema 迁移后 seed 两次，检查 16 个已批准报名、锁定名单、224 名成员、四组完整比赛、首页队数、八强等于小组前二，以及重复运行不重写历史锁定快照。

真实浏览器验收还发现旧 seed 规程只有顶层积分摘要，缺少正式报告所需 `results`。现补齐完整积分、同分、点球、弃权和八人制名单政策；内容变化追加已发布版本，保留旧 JSON。回归用真实信息员登录读取 seeded 待赛报告，断言双方 14 人、无阻塞且可编辑/提交。演示政策有明确标记，不代表采用了真实学校规程。

## 发布版实现

- H5 与业务 JSON API 要求真实账号会话；旧游客缓存、伪造角色、无效/过期会话不能授权。健康检查和媒体保持现有用途。账号边界保留 Taro 页面实例，未验证时隐藏页面并停止弹层，修复深链空白；同名平台 fallback 提取独立模块，避免手机递归解析。
- 管理后台实际创建球队和球员，球员加入 ACTIVE 球队成员关系后在组织目录与 H5 可见。社区成员和赛事锁定名单来源分别说明；新增球队不会自动变成参赛队，赛事队数仍为 16。
- 队长球队资料、成员资料、阵容保存使用组织/角色范围、版本冲突、幂等和审计约束。阵容明确区分首发、替补、未入选，保存后刷新从同一云端版本恢复；私有战术阵容不充当正式比赛出场事实。
- 比赛详情使用真实 API 出场/事件：首发、替补、进球助攻和配对换人。未公布名单、阵型或站位显示未公布，不猜测首发/位置。弹层支持桌面与手机、关闭/返回/键盘和原入口焦点恢复。
- 信息员报告通过实际 HTTP 工作流保存、提交、退回、确认及更正，支持全部事件类型、编辑时间、撤销恢复原事件 ID、重复校验和不可变历史。管理员确认前保留原正式结果。登录粒子中的 CCNU 图形已移除。
- 保留 main 的私信限制：只有 `PLATFORM_ADMIN` 且 `PLATFORM` 范围可发送；其他账号可读取历史。单身份标志选择仅展示本人现有身份，不授予权限。

## 浏览器证据与边界

验收使用本任务 API `3201`、H5 `3200`、后台 `3202`，均限回环地址；API 为 production 运行，禁用演示身份恢复/短密码。临时数据库与新建 `FICTIONAL_BROWSER` 数据不进入正式库。浏览器为无可见窗口的真实 Chrome，使用 Playwright 驱动；实际登录与写入不 mock。账号断网用例仅对指定 `/auth/me` 或 `/auth/login` 注入浏览器请求失败，单独标记，重试随后访问真实 API。

实际验收分组如下，均无页面异常：

- 账号：桌面 10 + 手机 10 项全部通过；后续两端错误页/登录视觉复核 2/2 通过。每端实际覆盖未登录深链拦截、旧游客缓存、伪造会话、非法到期值、真实首次登录、篡改角色缓存后刷新、既有私信/单身份限制、账号验证断网重试、注销撤销令牌、登录断网重试。真实登录、身份和首页 HTTP 均为 200，注销后旧令牌及匿名请求 401。标题 22px、正文 16px、按钮实际 46px，登录粒子正常且无 CCNU 图形。
- 球队：桌面/手机 17/17 通过，页面异常、console.error、相关 API 4xx/5xx 均为零。实际后台创建与 H5 显示、队长资料、成员位置 CAS/幂等/原因保存刷新、恢复原位置、8 首发阵容首发/替补/未入选、同一计划版本刷新恢复；手机成员控件实际 44px/14px。新增社区球队 0 场，赛事参赛数仍 16。合法长姓名两宽度只读显示复核 5/5 通过，手机 680px 表格在自身容器横滚，姓名未与来源标记重叠，文档仍为 390px。
