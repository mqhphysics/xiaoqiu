# 邮箱验证码：QQ授权码与本机启用

2026-10-08。本轮实现位于 `codex/email-auth`，主目录与日常3000仍使用原版本；没有合入main、推送或部署。代码检查通过也不表示真实邮箱送达。

## QQ邮箱要做什么

用户截图中的“POP3/IMAP/SMTP/Exchange/CardDAV 服务（未开启）”就是需要开启的入口。点击“开启服务”，按QQ提示验证本人身份，再点击“生成授权码”，得到16位授权码；界面位置以QQ当前页面为准。官方说明：[生成授权码](https://help.mail.qq.com/detail/106/985)。发件人已在本机忽略配置中预填用户指定邮箱，不写入本指南或Git。

授权码是服务器使用的邮箱专用密码；每封邮件里给用户的6位验证码由晓球安全随机生成，两者不同。程序只使用SMTP发信，不读取收件箱。不要把QQ登录密码或授权码填写到网站验证码输入框。

这里只检查SMTP网络/TLS/认证，不发送邮件。`SMTP_CONNECTION_AUTH_OK`不能当成送达证明；还要用真实可收信邮箱从网站申请验证码，分别检查收件箱与垃圾箱。

## 三条用户流程

- 注册：填写邮箱→获取验证码→验证码和实名注册资料提交→创建账号并标记邮箱已验证。
- 登录：已验证绑定邮箱→获取登录验证码→提交→使用既有会话协议登录。
- 找回：已验证绑定邮箱→找回验证码→新密码/确认密码→重置并撤销该账号全部旧会话→密码重新登录。

旧账号先用密码登录，到“我的”编辑资料/本人账号信息处验证当前保存的邮箱。要更换邮箱，先保存新邮箱，再验证；普通资料更新和管理员邮箱修改均清除旧验证状态。邮箱验证不会自动授予学生认证或管理权限。

邮件服务未配置时，验证码请求返回503；服务已配置时返回202“请求已受理”，不宣称已送达。未知或未验证账号申请找回/邮箱登录也返回相同202，避免泄露账号存在情况。外部SMTP异步失败会记录FAILED状态和审计，失败记录不能被用于注册或恢复；管理人员可检查失败审计和SMTP连接。API重启可能中断尚未发送的请求，用户60秒后可重试；此版未增加持久化邮件队列或自动重试。

## 技术与检查边界

User新增 `emailVerifiedAt`；验证码表保存邮箱、用途、组织、用户、HMAC摘要、过期/错误次数/发送/消费状态，不持久保存明文验证码。验证码5分钟有效、一次消费；每邮箱60秒冷却/每小时5次、每IP每小时20次、全局每小时200次，单码最多5次错误。限流在PostgreSQL预约事务中执行，适合当前小规模；阈值是本站初始策略，不是QQ发信额度保证。

邮箱验证/消费与注册/登录/改密共用事务和邮箱锁。数据库中的旧邮箱不自动标记已验证；组织选择必须是有效组织，验证码和操作绑定用途、邮箱、组织及目标用户。通过验证前不修改密码。改密通知不包含密码；通知失败不回滚已成功的密码修改。

独立数据库+真实HTTP使用记录邮件适配器，验证应用行为；浏览器测试在独立无界面窗口读取分支构建，API503用明确测试替身验证错误显示与请求路径，未访问用户数据或另开预览端口。二者均不是QQ邮箱真实送达证据。
