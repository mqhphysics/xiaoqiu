# 小程序怎么先看一眼，再做真机验收

> 2026-10-01 · 这是后续测试指南。本轮没有安装工具、构建小程序、扫描预览或更改 AppID。

## 1. 先区分三件事

| 方式 | 能检查什么 | 不能替代什么 |
| --- | --- | --- |
| 手机浏览器打开 H5 | 页面窄屏布局、触摸、网页流程 | 微信运行环境、权限与小程序 API |
| 电脑微信开发者工具的模拟器 | 小程序编译结果、路由、API 请求、组件行为 | 实际手机性能、相册、键盘、后台恢复 |
| 手机微信预览/真机调试 | 微信环境中的真实体验、联网和平台 API | 服务器部署与正式发布验收 |

晓球使用同一套 Taro + React 源码，所以改共享页面时可能同时影响 H5 与微信端；同一源码不保证两端外观/行为一样。H5 专用组件、DOM、鼠标、全屏、上传处理尤其要分别检查。

按用户安排，先收尾 H5，之后在独立手机任务里做这些测试；现在不需要马上发布小程序。

## 2. 当前项目配置是什么

- 代码与项目配置：`apps/mini-program/`。
- `project.config.json` 中 `miniprogramRoot` 为 `dist/`。
- `appid` 目前是 **`touristappid` 游客占位**，不是已经申请好的微信测试号或正式 AppID。
- 默认编译的 API 地址为 `http://127.0.0.1:3001`，组织 ID 未配置时回退演示组织。
- `config/index.ts` 的 H5 与小程序目前都使用 `outputRoot: 'dist'`。
- 本轮检查主目录未见 `dist/app.json`，不能把已有输出目录视为当前有效小程序包；本轮没有进行构建。

第一轮目标只是初看模拟器。如果微信工具要求有效身份/能力权限，先申请测试号，不把游客占位当成能扫码预览的保证。微信官方测试号支持开发测试和真机预览，创建项目时使用分配的 AppID。[微信官方：申请测试号](https://developers.weixin.qq.com/miniprogram/dev/devtools/sandbox.html)

正式项目 AppID 与开发者身份以后单独配置；本轮没有将账号/密钥写入仓库。

## 3. 第一轮：电脑模拟器

1. 从[微信官方下载页](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)准备开发者工具，用自己的微信登录。
2. 先固定本轮代码。建议在独立手机测试工作树准备依赖；不要同时在同一目录运行 H5 watch 和小程序 build。
3. 确认 API 已运行且 `/api/health/ready` 正常。当前本机 API 是 `3001`，模拟器初看可以使用本机地址。
4. 从准备好的工作树根目录执行以下命令。这是静态编译，不需要用 Seed 重置数据库：

```powershell
$env:TARO_APP_API_BASE_URL = 'http://127.0.0.1:3001'
npm --prefix apps/mini-program run build
```

5. 在微信工具导入**该工作树下的 `apps/mini-program`**，让工具读取 `project.config.json`；不要导入仓库总目录或 React 的 `src/`。当前配置把小程序内容定位到 `dist/`，构建后应有 `dist/app.json`。
6. 游客 AppID 只能按工具允许的范围初看；需要测试号时使用实际分配的 AppID。开发调试阶段可按微信官方说明暂时关闭合法域名校验，不能据此声称正式网络配置已完成。[微信官方测试说明](https://developers.weixin.qq.com/miniprogram/dev/devtools/sandbox.html)
7. 先点游客，再检查首页、赛程、主队、数据、我的及详情返回；随后用演示账号验证登录、刷新、评论和主队。遇到问题记录页面、操作、工具控制台与网络错误。

这里访问的是本机现有 API 和演示库。完整报告/名单正式流程尚未接通，不要因为模拟器能展示演示事件就认为信息员录入已完成。

## 4. 为什么要先分开构建目录

同一工作区的 H5 和 weapp 使用同一个输出目录，后一次构建可能清理/覆盖前一次产物。开展多端任务前建议由唯一负责人调整：

```text
H5 产物：   dist/h5/
微信产物：  dist/weapp/
项目配置：  miniprogramRoot = dist/weapp/
```

Taro 官方提供按 `TARO_ENV` 拆分输出的做法。[Taro：多端同步调试](https://docs.taro.zone/docs/envs-debug)

这是后续建议，本轮没有改构建配置或 `project.config.json`。若先用独立工作树初看，可以暂时沿用原 `dist/`，但该工作树也不要同时跑两个目标。

## 5. 第二轮：手机微信预览

准备实际测试号/正式 AppID 和对应开发者权限，点击工具“预览”并用手机微信扫码；具体能力以微信工具的账号状态为准。[微信官方：测试号预览](https://developers.weixin.qq.com/miniprogram/dev/devtools/sandbox.html)

手机里的 `127.0.0.1` 指手机自己，不能到达电脑 API。局域网联调需要：

- 手机与电脑在可互通的局域网；校园网隔离、VPN 或防火墙可能影响连接。
- API 监听可访问地址；当前源码默认监听 `0.0.0.0`，仍要核对运行环境。
- 将编译时 API 地址换成电脑局域网地址，再重新构建。例如下面的 IP 只是示意，必须替换成自己的电脑地址：

```powershell
$env:TARO_APP_API_BASE_URL = 'http://192.168.1.23:3001'
npm --prefix apps/mini-program run build
```

- 在受信任的本地测试网络核对该端口访问，不关闭整个 Windows 防火墙。微信官方允许局域网 IP 通信，但限制设备本机地址；开发时的调试选项和正式域名规则分别检查。[微信官方：网络说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)
- 微信图片地址也必须对手机可达；不能只替换 JSON API 地址而漏掉相对媒体 URL、`localhost` 图片或演示素材解析。

真正开放给测试者时改用可访问的 HTTPS API 与所需合法域名，避免要求每个学生打开开发调试模式。服务器配置和公开发布放在后续部署任务。

## 6. 最小检查清单

| 检查 | 重点 |
| --- | --- |
| 首次打开、游客、登录、退出、重新进入 | 页面不空白；会话和角色正确 |
| 底部五入口、主队按钮、详情返回 | 安全区、触摸、长队名、窄屏与返回状态 |
| 输入表单 | 键盘遮挡、注册长表单、错误消息、焦点 |
| 搜索、赛程、数据与主队 | 当前赛事一致；API 错误可重试；不偷偷回退 Mock |
| 图片、头像、上传 | 读取/上传权限、压缩结果、大小、取消选择、失败恢复 |
| 评论、评分、动态、私信 | 权限、刷新持久化；当前 WEB 照片选择器不会在微信中显示，要单独实现或清楚标记范围 |
| 后台/断网/弱网 | 草稿不丢、重复提交不重复写、过期会话可恢复 |
| 工作人员完整比赛流程 | 等正式名单/报告/审核接通后再用对应角色演练；不测试 Mock 当真流程 |
| iOS 与 Android | 至少各一台真实设备，记录微信版本和机型 |

构建通过、模拟器通过、真机通过、正式发布是四条不同记录。测试后报告“哪里通过、哪里失败、哪里还没测”，不要只写“小程序已经完成”。
