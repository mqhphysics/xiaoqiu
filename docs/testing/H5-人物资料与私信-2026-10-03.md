# 桌面 H5 人物资料与私信验收

本轮对应 [PLAYER-01 任务卡](../tasks/PLAYER-01-H5-人物资料与私信.md)，工作分支为 `codex/player-profile-dialog`。仅本地提交，未合并到日常主目录、推送或部署。

## 已完成的界面与接线

- 首页球员搜索、数据页球员榜、球队公开名单、比赛阵容及「我的」球员档案入口接入桌面资料弹窗；头像悬停显示卡片。主队页源文件没有修改，其内部接入另行安排。
- 弹窗人物摘要显示档案照片、号码、位置、球队、简介和统计。下方仅有「动态与数据」「比赛与资料」，能力图与基本资料放在后者。比赛状态筛选仅筛选接口返回的最近出场，没有编造未来参赛记录或单场评分。
- 悬停卡片使用现有校园足球图作默认封面；支持从头像移动到卡片、查看完整资料、关注与私信。门将使用扑救/解围字段布局，缺失值显示「待记录」。
- 私信右侧窗口改为联系人和对话两栏，保留搜索、未读数、发送、投诉、轮询及原有幂等标识。支持 Enter 发送、Shift + Enter 换行；阅读旧记录时刷新不强制滚到最后。
- H5 私信只在 App 挂载一次，避免保留的路由页面重复响应打开请求。资料与私信可以同时交互；焦点、Escape、关闭后的焦点恢复及页面滚动锁按窗口协调。切换账号时清理旧账号的消息界面状态。

## 未解决的数据来源及集成事项

1. 球员公开响应没有自选封面字段。本轮显示默认封面；`PlayerPresentation.coverUrl` 已准备好供经过确认的封面来源接入，上传/选择及持久化未做。
2. 当前比赛统计没有扑救、解围记录。本轮不以 0 代替缺失值；`PlayerPresentation.goalkeeperStats` 可接真实来源。
3. 球员公开响应没有关联 userId，消息目录也没有 playerId。本轮不会按同名匹配账号。默认「发消息」打开联系人选择，用户选择账号后可以使用原消息 API。提供可靠 `messageUser` 后即可直达本人会话。
4. 普通他人球员的作者账号关系缺失，不能准确筛出个人动态。当前本人档案可按 session 的 linkedPlayer.id 与 author.id 获取当前赛事的已公开动态；其他球员显示待补充，未来可以传入来源明确的 `presentation.posts`。
5. 主队页接入使用导出的 `PlayerProfileSections`，按 player.id 设置组件 key；该组件从两个选项开始，不包含摘要。完整摘要使用 `PlayerProfile`，悬停卡片可复用 `PlayerHoverCard`。调用方负责来源可信的账号、封面和门将统计。
6. 集成负责人需合入当前分支后在日常 3000 验证真实 API 读取、关注持久化、正确收件人及消息发送/读取；本轮未改主目录的分支或服务。

公共文件变更：无。公共文件建议：上述三种数据来源如需改变模型/契约，由集成负责人确定后另行安排；本轮未直接修改公共文件。
