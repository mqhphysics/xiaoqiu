## 问题原因与处理

原实现先等待 460ms 再 redirect，新页面又从头构建导航和内容。旧指示框同时变宽、变高、变形、淡出，主队的左右装饰线还与普通指示条使用不同机制。

逐帧实测另发现 Taro 默认对整个 `.taro_page` 使用 300ms 横滑；挂载时页面在屏幕外，导致位置测量偏移一个屏幕宽度，并带动顶部导航一起运动。本轮仅在宽度大于 720px 的 H5 公共壳层页面取消这层原生横滑，统一页面容器背景。导航位置在新页面首次绘制前恢复，再通过 Web Animations API 接续运动。全页从 0.72 透明度进入的旧效果在桌面关闭，短内容过渡从 0.94 开始。

加载骨架沿用已有 DataState 的真实加载条件和 aria-live 文本，使用 CSS 占位；不修改读取接口、不注入虚构内容，不增加页面缓存或改成单一宿主路由。
