# 公网空赛事与模拟业务联调

基线 `cf0c212`。公开登录成功后，首页仍显示“暂时无法连接赛事数据”。

## 根因和修复

`apps/mini-program/src/pages/index/index.tsx` 原先将所有加载异常放入 failed 状态并显示同一连接错误标题。
`selectPublicTournament` 在本组织没有可读的已发布赛事时返回 HTTP404，代码 `COMMON.NOT_FOUND`，消息“当前组织没有可读取的已发布赛事”。
新建私有联调组织确实没有赛季或赛事，不能从首页错误或日志 200 推断断网。
请求日志的 finalize 在 exception filter 写最终状态前执行，其状态不是此异常响应的可靠证据。

H5 收到首页404后再次读取本组织已发布赛事列表；只有真实200且列表为空才显示“暂无已发布赛事”。
网络、会话、权限、服务故障，以及错误默认赛事但存在其他已发布赛事，继续显示真实错误。
微信保持原加载行为；本轮没有微信构建或设备验收。

用户随后授权专用联调库导入现有模拟业务数据。导入前用 pg_dump custom 备份；只从独立演示库读取2026当前赛事的19种业务模型。
首次精确新增1476行，第二次新增0行，无冲突；16队、224虚构球员、四组各4队、组前二晋级8强，每队14人。
32场比赛（29结束、3未开始），580出场、80进球、29黄牌；已赛58个球队侧各8首发，未开始比赛没有出场或事件。
原账号/凭据/会话/会员/角色数量未变，用户已有球队所选业务字段摘要未变。没有复制账号、默认密码、报告作者或outbox，也没有伪造审核报告。
备份和含私有账号摘要的运行数据只在本机任务目录，不纳入Git或公开产物。

原后端仅将固定演示组织识别为 seed fixture。因此新增明确服务器设置 `DEMO_FIXTURE_ORGANIZATION_ID`，只允许一个有效UUID组织读取标为DEMO的既有演示赛事事实。
仍要求限定DEMO赛事编码且该赛事没有报告版本；其他组织继续正式赛果路径，认证、角色和对象范围保持原策略。
这项设置只用于用户已授权的隔离模拟联调，不应配置在正式赛事组织。

## 边界

只读业务服务诊断不是用户账号在生产HTTP中运行的自动化，也不是已登录公开页面的完整浏览器验收。
公开登录由用户实际反馈成功。导入后公开浏览器各业务页面、CSP修订发布、实体手机/Safari、长期稳定性和备份恢复仍需各自验证。
八人制新阵容/教练/媒体模块属于后续集成分支，不在这份联调热修中迁移公网schema。
