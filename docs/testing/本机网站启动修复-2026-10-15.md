# 本机网站启动修复验收（2026-10-15）

## 范围与原因

用户分配网站启动修复，另一任务负责小程序；正在运行的后端、数据库、运行版本不改，不开启公网。

基线 main `4f75a23`，独立分支 `codex/local-h5-startup-20261015`。任务开始时日常目录在另一任务的 `codex/weapp-preview-startup`，已有三个未提交的网站启动修复；在用户明确网站归本任务后保留并接续，未切换日常目录分支或修改小程序文件。

截图中管理端已构建成功，网站 3000 等待超时。实测 Windows Node.js 直接 spawnSync npm.cmd 返回 EINVAL；该调用藏在 H5 子进程中，父启动器原来未传播子进程退出状态，最后只显示泛化超时，并误导用户检查 Docker。

## 修改文件

- apps/mini-program/scripts/dev-h5.mjs：Windows 通过 Node 调用 npm-cli.js，报告实际 spawn 错误。
- scripts/start-shared-local.ps1：保存网站启动进程与句柄，传播真实退出码，管理端只由 dev:h5 构建一次；复用现有网站，成功明确返回 0。后端启动块不变。
- scripts/lib/wait-local-website.ps1：网站失败立即显示退出码和实际日志，编译期间提示进度，超时显示两个正确日志位置。
- scripts/desktop-entry/open-website.ps1：错误指向 shared-runtime，移除笼统的 Docker 归因；支持 NoBrowser 自动验证，正常双击仍在就绪后打开浏览器。
- scripts/tests/local-website-startup.ps1：真实失败子进程、超时日志、健康服务复用三项定向验证。
- 本轮任务卡与此验收记录。

四个日常启动相关文件已同步到主使用目录，内容与本任务一致。提交保存在独立分支；主目录继续由原任务使用，未合并 main、push 或发布网站。
