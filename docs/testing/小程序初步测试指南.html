3. 第一轮：电脑模拟器

  1. 从微信官方下载页准备开发者工具，用自己的微信登录。本机已经安装到 D:\software\WeChatDevTools。
  2. 可双击项目根目录的 打开晓球微信小程序.cmd；它按需启动本地服务、构建微信包并调用官方工具打开项目。首次连接可能需要在微信工具窗口确认 Codex 授权；游客 AppID 导入失败时仍需有效测试号/AppID。
  3. 确认 API 已运行且 /api/health/ready 正常。当前本机 API 是 3001，模拟器初看可以使用本机地址。
  4. 从准备好的工作树根目录执行以下命令。这是静态编译，不需要用 Seed 重置数据库：
$env:TARO_APP_API_BASE_URL = 'http://127.0.0.1:3001'
npm --prefix apps/mini-program run build
  1. 在微信工具导入该工作树下的 apps/mini-program，让工具读取 project.config.json；不要导入仓库总目录或 React 的 src/。当前配置把小程序内容定位到 dist-weapp/，构建后应有 dist-weapp/app.json。
  2. 游客 AppID 只能按工具允许的范围初看；需要测试号时使用实际分配的 AppID。开发调试阶段可按微信官方说明暂时关闭合法域名校验，不能据此声称正式网络配置已完成。微信官方测试说明
  3. 先点游客，再检查首页、赛程、主队、数据、我的及详情返回；随后用演示账号验证登录、刷新、评论和主队。遇到问题记录页面、操作、工具控制台与网络错误。

这里访问的是本机现有 API 和演示库。完整报告/名单正式流程尚未接通，不要因为模拟器能展示演示事件就认为信息员录入已完成。

4. 为什么要先分开构建目录

本次已将 H5 和微信输出拆为同级目录，避免后一次构建清理/覆盖另一端产物：

H5 产物：   dist/
微信产物：  dist-weapp/
项目配置：  miniprogramRoot = dist-weapp/

Taro 官方提供按 TARO_ENV 拆分输出的做法。Taro：多端同步调试

H5 原有输出路径保持可用。微信的 ES6 转 ES5 与增强编译一并关闭，让工具读取 Taro 已编译的产物；运行时行为仍需在模拟器检查。

5. 第二轮：手机微信预览

准备实际测试号/正式 AppID 和对应开发者权限，点击工具“预览”并用手机微信扫码；具体能力以微信工具的账号状态为准。微信官方：测试号预览

手机里的 127.0.0.1 指手机自己，不能到达电脑 API。局域网联调需要：

  • 手机与电脑在可互通的局域网；校园网隔离、VPN 或防火墙可能影响连接。
  • API 监听可访问地址；当前源码默认监听 0.0.0.0，仍要核对运行环境。
  • 将编译时 API 地址换成电脑局域网地址，再重新构建。例如下面的 IP 只是示意，必须替换成自己的电脑地址：
$env:TARO_APP_API_BASE_URL = 'http://192.168.1.23:3001'
npm --prefix apps/mini-program run build
  • 在受信任的本地测试网络核对该端口访问，不关闭整个 Windows 防火墙。微信官方允许局域网 IP 通信，但限制设备本机地址；开发时的调试选项和正式域名规则分别检查。微信官方：网络说明
  • 微信图片地址也必须对手机可达；不能只替换 JSON API 地址而漏掉相对媒体 URL、localhost 图片或演示素材解析。

真正开放给测试者时改用可访问的 HTTPS API 与所需合法域名，避免要求每个学生打开开发调试模式。服务器配置和公开发布放在后续部署任务。

6. 最小检查清单

检查重点
首次打开、游客、登录、退出、重新进入页面不空白；会话和角色正确
底部五入口、主队按钮、详情返回安全区、触摸、长队名、窄屏与返回状态
输入表单键盘遮挡、注册长表单、错误消息、焦点
搜索、赛程、数据与主队当前赛事一致；API 错误可重试；不偷偷回退 Mock
图片、头像、上传读取/上传权限、压缩结果、大小、取消选择、失败恢复
评论、评分、动态、私信权限、刷新持久化；当前 WEB 照片选择器不会在微信中显示，要单独实现或清楚标记范围
后台/断网/弱网草稿不丢、重复提交不重复写、过期会话可恢复
工作人员完整比赛流程等正式名单/报告/审核接通后再用对应角色演练；不测试 Mock 当真流程
iOS 与 Android至少各一台真实设备，记录微信版本和机型

构建通过、模拟器通过、真机通过、正式发布是四条不同记录。测试后报告“哪里通过、哪里失败、哪里还没测”，不要只写“小程序已经完成”。
