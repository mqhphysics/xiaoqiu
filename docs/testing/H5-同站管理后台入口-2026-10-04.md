基线 `a365f43b39709cf5c2ce06178020e88522f7641d`，独立分支 `codex/admin-sites-portal`。
本任务只实现已有管理端的静态同站构建与会话适配，不新增服务器、依赖、数据库迁移或部署资源。

## 构建与部署

配置以下非敏感环境变量后运行 `node scripts/build-sites-bundle.mjs`：

```text
TARO_APP_API_BASE_URL=https://<API 域名>
TARO_APP_ORGANIZATION_ID=<组织 UUID>
```

脚本先运行管理端类型检查、H5 生产构建和 Vite `build --base /admin/`，再将当前工作树的管理端产物复制至 `apps/mini-program/dist/admin/`。
部署完整的 `apps/mini-program/dist`，保留其中的 `admin/` 子目录；`/admin/` 应返回其自己的 `index.html`，不能统一重写到 H5 首页。
`site-bundle.json` 仅记录组织 UUID、API 地址、静态入口和会话桥标志，不包含账号或凭据。
复制与删除前检查路径属于脚本所在仓库，拒绝穿过 junction/symlink；不写其他工作树的 dist。
公开 API 必须使用 HTTPS，隔离 QA 可使用 HTTP loopback；拒绝 URL 内用户名、密码、查询参数和片段。
两个客户端使用同一 API 和组织配置，短密码模式强制关闭。现有独立 Vite 开发与后台账号登录保留。

## 登录衔接

生产合并构建显式设置 `VITE_H5_SESSION_BRIDGE=1`。
管理端仅在 `/admin/` 读取当前浏览器窗口同源的 `localStorage`，不访问 opener、其他域名、浏览器资料或外部存储。
适配已有 Taro `xiaoqiu.session.v1` 的 `{data: AuthSession}` 形状，检查有效期、令牌形状、用户 UUID 和固定组织 UUID。
只将令牌与有效期放入未验证的后台状态，缓存中的姓名、权限、角色和其他个人字段不提供后台授权。

首次进入及换号必须由真实 `GET /api/auth/me` 成功后验证固定组织和既有 `adminKind` scope，才能显示管理工作台。
TEAM_COACH、普通用户、跨组织 ORGANIZATION_ADMIN 和错误 scope 不获得管理权限。
回到窗口/标签页重新检查身份；撤销、权限变化或验证失败会退出工作台或显示验证错误。
普通用户尝试打开后台仅被拒绝，不主动撤销其 H5 账号的服务器会话。
后台退出仍调用真实 `/api/auth/logout`，同步清除相同令牌的 H5 适配器；晚到的旧账号响应不能删除新账号。
H5 在其他标签页换号或退出时，后台丢弃旧身份和工作台数据，新账号仍需重新验证。
后端每个对象的组织、角色和范围授权继续生效，入口及缓存不替代这些检查。
