# 晓球 V1 演示验收手册

> 本手册用于本地演示验收。赛事、账号和统计均为 `DEMO_FIXTURE` 虚构数据，不得当作真实学生信息或生产账号使用。

## 1. 当前演示内容

- 2026 绿茵杯：16 支球队、28 场比赛（25 场已结束）、224 名完整球员；每队 14 人，比赛按八人制统计。
- 前 8 队保留历史小组赛数据；为完整演示淘汰树，本轮按“16 队均晋级”的假设签位增加十六强、八强、半决赛、三四名赛和决赛，不代表真实竞赛规程。
- 已结束比赛包含比分、出场、进球、助攻、红黄牌、评分和观赛评论。
- 2025 历史赛季：8 场已结束的淘汰赛，用于验证赛季切换；两个赛季合计 36 场。
- 6 条官方/社区内容及其点赞、评论。
- 首页、赛程、数据、主队、我的五个核心入口，以及比赛、球队、球员、动态详情。
- 球队/球员关注、队长管理、消息、私信、投诉反馈、头像裁剪上传等账户与社区闭环。

## 2. 首次启动

推荐从仓库根目录运行一键启动脚本。它不依赖全局 `pnpm`，会启动 PostgreSQL、执行迁移与 Seed，并分别打开 API 和 H5 窗口：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-local-demo.ps1
```

启动完成后访问 `http://127.0.0.1:10087/`。如只准备数据库而不启动服务，可追加 `-PrepareOnly`；如明确需要保留当前演示数据，可追加 `-SkipSeed`。

下面是等价的手动流程。先准备并启动 PostgreSQL：

```powershell
Copy-Item infra/.env.example infra/.env
docker compose --env-file infra/.env -f infra/compose.yaml up -d postgres
docker compose --env-file infra/.env -f infra/compose.yaml ps
```

在同一个 PowerShell 窗口初始化数据库并启动 API：

```powershell
$env:DATABASE_URL = 'postgresql://xiaoqiu:xiaoqiu-local-only@localhost:5432/xiaoqiu'
$env:API_PORT = '3001'
npm --prefix apps/api run db:migrate:deploy
npm --prefix apps/api run db:seed
npm --prefix apps/api run dev
```

看到 Nest application successfully started 后保留窗口。在第二个 PowerShell 窗口启动 H5：

```powershell
$env:TARO_APP_API_BASE_URL = 'http://127.0.0.1:3001'
npm --prefix apps/mini-program run dev:h5
```

访问：

- H5：`http://127.0.0.1:10087/`
- API 健康：`http://127.0.0.1:3001/api/health/ready`
- API 文档：`http://127.0.0.1:3001/api/docs`

Seed 可以重复执行。需要恢复初始演示内容时，停止 API 后重新执行 `db:seed`。

## 4. 建议验收路线

### 4.1 首页与搜索

1. 打开网站先看到独立登录页；选择游客浏览后，应看到 `2026 绿茵杯 · 演示赛季`、首场半决赛结果、官方公告和焦点赛程。
2. 在首页、赛程、主队、数据、我的之间切换；顶部导航应始终留在原位，选中项快速连贯地轻跳，只有下方内容更新且没有整页闪白。
3. 首页默认只显示单行紧凑搜索框；输入 `物院` 并提交后才进入搜索结果态并显示“全部/球队/球员/动态”筛选，清空或返回后恢复首页内容。
4. 切换到“球员”并搜索 `高星野`，进入后应看到号码、位置、惯用脚、年级专业、简介和赛季统计。
5. 焦点赛事保持一行、按时间从左到右排列；点击“查看全部”进入赛程，不应在首页堆叠成两行大卡片。
6. 点击首场半决赛，默认应看到 4.7 分、3 人评分和三条观赛评论；再切换比赛事件与双方阵容。
7. 首页动态区的点赞和评论使用紧凑图标；点击发布入口应打开独立发布层，可输入表情，发布后刷新仍可见。

### 4.2 赛程与数据

1. 进入“赛程”，分别选择全部、未开始、已结束，并切换日期正序/倒序。
2. 已结束比赛必须显示比分，未来比赛显示时间和场地；日期标题应明显，单场卡片保持紧凑。
3. 在比赛卡片中点击队徽应进入对应球队；点击比分、场地或卡片其余区域应进入比赛详情。
4. 进入“数据”，确认概览显示 16 队、28 场、25 场已结束。
5. 积分榜应显示完整球队名和积分；射手榜、助攻榜可进入球员档案。
6. 查看细线精确连接的 16 队淘汰赛晋级树：物院一队已进入决赛，另一场半决赛待赛；再切换到 2025 赛季。

### 4.3 主队与完整名单

1. 未登录进入“主队”，应看到 16 支球队和登录提示。
2. 使用 `student` 登录后再次进入，默认主队为“数院星火”，并显示 14 人完整阵容。
3. 顶部关注条用加号打开管理层；可搜索并关注球队或球员，可取消关注，刷新后结果仍保留。
4. 已关注项目可从顶部直接切换；桌面端右键或管理层内的取消操作应可移除关注，不出现占满首屏的“管理关注”横条。
5. 主队近期赛事保持一行并提供“查看全部”；球队动态优先出现，赛程、数据和完整阵容按需展开。
6. 任意进入一支球队，检查简介、口号、教练、队长、战绩、近期比赛和按门将/后卫/中场/前锋分组的 14 人名单。
7. 任意点击普通球员，出场次数、首发次数和比赛记录必须一致，不能只给进球者显示统计。
8. 使用 `captain` 打开队长工作台：能处理加入申请、调整当前成员位置、移出成员，并能区分“当前成员”与只读的赛事报名快照。

### 4.4 登录与社区写入

1. 使用 `student`、`知夏看球`、`林知夏`、`20249990001` 分别登录，四种标识都应进入同一账号。
2. 退出后依次手动输入五个账号，确认“我的”中昵称、实名、完整本人学号、身份标签、关联球员和角色入口不同。
3. 使用 `student` 查看实名目录应被拒绝；使用 `admin` 应看到本组织五个账号的完整学号和邮箱。
4. 点击“忘记密码”，使用林知夏和 `20249990001` 设置新密码；验收后重新 Seed 可恢复公共演示密码。
5. 登录后回到首页，点赞一条动态并刷新，点赞状态应保留。
6. 发布一条测试动态，进入详情后发表评论，刷新后内容仍存在。
7. 退出登录后，发布、点赞和评论应要求重新登录。
8. 在已结束比赛提交 1-5 星和评论，刷新后评分应保留；待赛比赛必须提示赛后开放。
9. 在“我的”中修改昵称与绑定邮箱，刷新后应保留；点击头像选择图片后必须先进行正方形/圆形裁剪预览，确认后服务端统一保存为不超过 320×320、72 KiB 的 WebP。
10. 用不同账号完成点赞、回复、申请入队后，接收方的消息中心应分别显示对应通知并支持标记已读。
11. 从用户入口打开右侧私信抽屉，搜索成员并互发消息；切换联系人时不得把草稿或旧会话串到新联系人，收到的单条消息可以投诉。
12. 对动态、评论、比赛评价或私信提交投诉/反馈；使用 `admin` 在处理中心看到目标预览，能隐藏内容、回复处理结果，提交人能在“我的投诉”中查看状态和回复。

### 4.5 响应式与异常状态

1. 桌面浏览器检查“首页、赛程、圆形主队、数据、我的”；窄屏检查同顺序底部 Tab 均完整可点。
2. 左侧平台名、中间五个导航、右侧用户名应保持对称；右上角头像/用户名没有多余下箭头，点击后自然展开菜单。
3. 进入比赛、球队、球员或动态详情后，左上角应有可用的返回按钮。
4. 返回箭头应准确居中；手机宽度下不得出现页面级横向滚动、比分卡片裁切或文字覆盖。
5. 暂停 API 后刷新，应显示明确错误与“重新加载”，不能静默退回 Mock 数据。
6. 打开发布、举报、头像裁剪或私信层后，Tab 焦点应留在当前浮层；Escape 只关闭最上层，关闭后焦点回到触发按钮。

## 5. 微信开发者工具

先构建小程序：

```powershell
npm --prefix apps/mini-program run build
```

在微信开发者工具中导入 `apps/mini-program`。项目配置已将 `dist/` 设为小程序目录，并使用测试 AppID。模拟器访问本机 API 时保持 API 在 `3001` 端口运行，并关闭开发阶段的合法域名校验。

真机不能用手机自己的 `127.0.0.1` 访问电脑。真机联调时需把 `TARO_APP_API_BASE_URL` 设置为电脑局域网地址后重新构建，并允许 Windows 防火墙访问该端口。V1 发布前还需要单独完成开发者工具和真机验收。
