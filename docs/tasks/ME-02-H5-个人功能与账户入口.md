# ME-02 桌面 H5 个人功能与账户入口

日期：2026-10-08。依据用户本轮截图、口述及三次补充，更新 ME-01 的桌面布局要求。

## 本轮授权范围

- 桌面「我的」页面：去掉顶部身份横条和旧右侧板块；左侧放核心功能卡片，右侧缩窄动态/关注比赛/收藏；个人背景在头像后展示，右上角小按钮更换。
- 个人信息：头像、昵称、背景、简介、姓名、学号、邮箱按左展示、右操作排列。
- 身份管理：认证/申请身份及选择展示身份放在同一入口。
- 顶部账户区域：只显示头像，悬停出现账户菜单；消息使用独立信件按钮；信息员另设笔形录入按钮，弹窗选择按时间排列的授权已赛比赛。
- 设置：放在问题反馈上面，修正桌面错位并增加实际生效的偏好。
- 球队关系：根据球员/队长教练/其他身份显示我的球队、管理球队或加入球队；使用独立弹窗，加入转会申请，保留球队关系与主队偏好的区别。

用户本轮明确要求顶部账户与设置改动，优先于旧 ME-01「不改共享导航」的限制；仅修改账户工具区域，不改五入口导航逻辑及主队装饰。

独占写入范围为 `pages/me/`、`components/public-shell/` 的账户组件与必要接线、`components/settings-dialog/`、`features/managed-media/` 的 H5 上传控件、`features/match-report/` 的 H5 选赛弹窗及本任务文档。不修改模型、契约、生成客户端、依赖、锁文件或微信专用代码。

## 实现边界

现有 API 支持本人昵称/简介/邮箱更新、头像上传、背景投稿、身份申请/标志偏好、球队关系/入队申请、反馈记录及比赛报告。姓名/学号本人直接修改、邮箱验证码验证、专用转会状态机与自动成员迁移没有现成接口。

姓名/学号更正使用真实反馈申请；转会选择原球队/目标球队/原因后，使用既有 FEEDBACK 记录交管理员处理。界面明确当前归属及赛事名单不会自动改变，不能将反馈记录称为转会已完成。

验收证据和需要协调事项见 [本轮验收](../testing/H5-个人功能与账户入口-2026-10-08.md)。完成检查后自行本地 commit；没有 push、合入 main、更新日常预览或部署授权。
