> 状态：本轮实现与全套 API 检查完成，结果见[验收报告](../status/后端第一轮改进与验收-2026-10-01.md)。

## 范围与所有权

主任务是本轮唯一代码写入者，在当前 `codex/h5-refinement` 分支工作；辅助审查只读，不产生并行代码写入。保留其他任务对 `tools/` 等目录的修改。

独占本轮写入：`apps/api/src/auth/` 中服务及对应测试、`apps/api/src/social/` 中服务及对应测试、必要的 API 缓存响应配置，以及新增后端验收/后续任务文档。全套回归发现的既有演示球队动态映射缺失，可在 `apps/api/src/database/seed-demo-social.ts` 定向补齐映射；不运行 Seed。现有 API 的路径与请求/响应结构保持兼容。

不修改前端页面、H5 会话代码、小程序、公共 schema、依赖、锁文件、contracts 和生成 API Client；不实现新的比赛报告/报名模型。

## 本轮交付

- 登录标识歧义与唯一约束冲突处理，补会话失效回归。
- 本地弱身份恢复限制在显式开启的演示账号，不用于真实账号。
- 反馈长回复、重复审核、终态/隐藏记录及通知读取的兼容修复。
- 管理员收件人和无队长时的入队申请接收兜底，保留对象与组织隔离。
- 敏感/个人 API 的缓存边界，保持刷新读取服务端身份。
- 独立测试数据库的真实 HTTP 角色往返；不能把单元替身当真实数据库验证。
- 文档列出已做/未做/验证边界与后续较大分支任务。

## 验收

1. 同名截断不导致错误登录；唯一标识登录不被昵称抢占；会话撤销/过期/禁用生效。
2. 反馈 1000 字回复可保存，通知摘要不超字段长度；同一审核重试不重复写审计/重置已读。
3. 终态不被普通审核重开，隐藏记录不丢失；未授权角色不能审核。
4. 入队申请有有效收件人兜底；重新申请可出现在通知列表，重复已读不改首次读取时间。
5. 后端类型、相关单元测试和独立 PostgreSQL 往返检查通过；未跑项目明示。
6. 仅提交本轮自己的文件，不推送、不合并其他分支。
