# V2-03 比赛报告与审核

分支 `codex/v2-match-report`，独立聊天“设计比赛信息录入交互”。用户明确要求入口、舒适输入、取消、按保存形成版本、查看比较历史；同时补真实后端。

独占新增 apps/api/src/match-report、features/match-report、quick-report的 .h5.tsx、readonly-match-detail 的H5入口；原共享quick-report和微信配置行为保留。不改公共导航/首页/登录，不写其它worker模块。schema/migration/app.module接线由Integrator做。

完整SAVE/SUBMIT/RETURN/CONFIRM/CORRECT、CAS、clientActionId幂等、固定名单/规程历史与字段验证依[公共契约](../architecture/V2-工作流公共契约.md)。角色用真实枚举和auth helper，号码保留字符串；前端事件clientEventId不当数据库UUID。

只有CONFIRM同事务投影官方比分/事件、审计、通知及唯一命名match.report/MatchReportConfirmed任务；更正产生新草稿，旧确认版仍有效直到新确认。审核不得偷换fields/context；点球不混普通比分；ABANDONED不是双方弃权。

历史只读比较不覆当前草稿；显式“带入草稿”与取消确认、网络不确定原键重放。真实PG/HTTP覆盖角色范围、并发、重试、历史不可变、确认/更正、错误/通知回滚；H5真实API走保存→审核→回读。只有页面或Mock不算交付。commit自己的成果，由Integrator验收。
