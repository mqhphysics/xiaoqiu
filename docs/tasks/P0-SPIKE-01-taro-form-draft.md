不得修改根配置、公共 packages、其他 apps 或 `pnpm-lock.yaml`。

## 目标

用一条“快速比赛报告”纵向原型验证 Taro 小程序端复杂表单、草稿恢复、弱网和版本冲突体验，不接真实后端。

## 工作内容

1. 新增快速比赛报告 Spike 页面，至少包含：
   - 主客队比分
   - 比赛状态或异常结果
   - 可动态增删的进球事件
   - 备注
   - 提交确认
2. 使用 mock repository 隔离数据访问，禁止把 mock 逻辑散落在页面组件中。
3. 实现本地草稿：
   - key 包含 `matchId`、`userId`、`reportType`
   - 修改后 debounce 保存
   - 进入页面检测和恢复
   - 提交成功或主动丢弃后删除
4. 模拟以下状态：
   - 正常提交
   - 网络失败后保留草稿
   - 服务端 `baseVersion` 变化并展示冲突对比
5. 页面进入后台时停止请求行为，恢复前台后按需继续。
6. 编写 Spike 报告，记录验证结果、阻塞点、保留建议和后续 API 契约建议。

## 约束

- 这是技术验证，不建立正式赛事领域模型。
- 页面交互需同时兼容微信小程序和 H5 构建。
- 优先复用现有组件和项目风格，不引入重量级状态管理。
- 若需要依赖，只修改 `apps/mini-program/package.json` 并在完成报告中列出，不修改锁文件。

## 验收标准

- 可以完成草稿保存、退出后恢复、提交和删除。
- 网络失败不会丢失用户输入。
- 版本冲突时可以查看“我的提交”和“当前数据”，且不会静默覆盖。
- 微信小程序与 H5 构建通过。
- 类型检查通过，并为草稿 key、恢复判断或冲突合并中的纯逻辑添加测试。
- Spike 报告明确给出“通过 / 有条件通过 / 不通过”结论。
