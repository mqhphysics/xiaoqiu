3. 会改变日常操作的边界

  1. 重名组超过 10 人时请用自己的用户名、学号或邮箱。账号标识存在时，不再用撞名的其他账号密码登录；跨字段匹配也须密码唯一。
  2. 反馈已经 RESOLVED/REJECTED 后，普通审核接口只能幂等重试原决定，修改/重开返回 409。申诉和重新打开需要后续显式流程，不静默覆盖。
  3. 仅 TOURNAMENT_ADMIN 不会被本轮提升为组织管理员。组织级反馈权限保持原边界；赛事范围内的内容审核需要另定授权。
  4. 姓名+学号 找回默认关闭。仅纯演示环境可由运行环境显式设置 ENABLE_DEMO_IDENTITY_RECOVERY=true，生产模式仍禁止，真实账号不会被此开关放行。正式邮箱/人工核验找回尚未接通。
  5. 会话仍有固定七天有效期；本轮没有加自动续期、令牌轮换或踢出设备的设置页面。

4. 本轮没有做完的内容

  • 前端刷新/会话同步：旧请求 401 可能清掉新登录；角色/资料缓存可能滞后；损坏的过期时间可能通过校验。这些在 H5 功能任务中处理，本轮不改用户正在调的页面/会话代码。
  • 设置：主题、通知开关、多设备会话管理尚无完整持久化模型/契约和入口；不能把“即将开放”按钮记作功能已实现。
  • 正式权限与赛事来源：赛程/名单 API 的开发权限头、演示赛事默认选择仍需正式替换。
  • 正式赛事名单：队长入队申请属于成员关系，仍不等于报名提交/管理员退回/批准/锁定名单。
  • 信息员比赛报告：事件录入、报告提交/确认/更正、正式比分与榜单/晋级一致性仍需要完整后端模块。
  • 通知运营：目前站内持久化、最近 100 条读取；未做历史分页、外部推送、无人值守告警或完整反馈申诉。
  • 生产与手机：本轮没有服务器发布、微信开发者工具或真机验收。

后续分支建议及可直接分配的验收条件见后端并行任务方案。
