## 接口与保存语义

| 接口                                                  | 行为                                                                                      |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `GET /roster/tournaments/:tournamentId/teams/:teamId` | 当前报名、工作名单版本、资格候选、最新锁定快照编号                                        |
| `POST .../commands`                                   | `SAVE/SUBMIT/RETURN/APPROVE/LOCK/REOPEN`，必须携带 `expectedVersion` 和 `Idempotency-Key` |
| `GET /captain/teams/:teamId/lineup-plans`             | 本队私有战术及单场阵容计划                                                                |
| `POST /captain/teams/:teamId/lineup-plans`            | 首建 version 0；更新明确 planId；只在明确保存时新增版本                                   |
| `GET .../:planId/revisions`                           | 不可变保存历史，按版本游标分页                                                            |

队长选手使用 `PlayerProfile.id`，不会根据姓名匹配、合并或覆盖档案。报名名单与战术计划分别保存，战术保存不会生成比赛出场统计。

战术 payload 为 `formation/format/slots/benchPlayerIds`；位置保存 `slotId/label/x/y/playerId`，x/y 为 0–100 的球场百分比坐标。普通战术可保留空位；单场阵容需完整首发、一个门将、首发/替补唯一，并绑定本组织、本队、本场赛事的锁定名单。
