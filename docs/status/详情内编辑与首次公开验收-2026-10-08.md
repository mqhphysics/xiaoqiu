| Before                                                     | After                                                                         | Why                          |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------- |
| 右侧录入按钮，管理员也显示入口                             | 顶部居中；仅本场 MATCH/TOURNAMENT 范围有效 MATCH_REPORTER 显示                | 使用后台真实资格而非展示身份 |
| 跳到三步报告页面                                           | 旧 H5 编辑组件删除；旧链接转至比赛详情并进入编辑                              | 编辑就在用户正在看的比赛里   |
| 分别添加比分和事件                                         | 比分可直接输入，红黄牌/换人数量生成对应事件行；填写球员、分钟及补时后自动排序 | 数量与明细保持一致           |
| 保存/提交按钮和说明占据多个区域                            | 编辑时评分/阵容 Tab 隐去，底部一个宽“完成编辑”按钮                            | 集中完成本场录入             |
| 完整报告先等待审核                                         | 首个通过校验的完成版本立即公开；并发较晚版本保存为 SUBMITTED，不覆盖正式结果  | 用户明确更新的发布规则       |
| 发布后继续直接编辑                                         | 居中“申请修改”；申请真实保存并通知管理员，管理员开启更正后才能继续            | 已发布记录保留版本与审计     |
| 重复事件标题、总条数、每行球队名和说明、阵容默认提示等小字 | 删除可见冗余，事件用小队徽识别球队；默认站位仍由 aria/data 标注               | 节省空间而保持必要识别信息   |

未完成的内容可通过关闭按钮保存为真实草稿，重新进入显示“继续编辑”。空白分钟/球员只能保留于有开始凭据的草稿；完成仍严格验证锁定名单、进球比分对应、时间范围、配对换人和重复事实。

数据库事务锁定本组织的比赛行。开始凭据绑定真实操作者、组织、对阵/赛制/时间和锁定名单/规程；第一次成功完成产生 CONFIRMED 与正式事件/比分、确认 Outbox。已在编辑中的后来请求保留完整不可变版本，管理员可在既有报告历史中查看；新进入者不能伪造旧 expectedVersion 绕过已完成限制。
